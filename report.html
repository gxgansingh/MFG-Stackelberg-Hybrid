Experimental Report

1. System Architecture & How the Framework Works

This framework models a three-tier IoT Edge Computing architecture (IoT Task Generators, Follower Edge Nodes, and Leader Edge Servers) through five sequential stages:

  1. Topology & Workload Generation (generator.py): Instantiates Network-1 (50 nodes, 5 servers), Network-2 (150 nodes, 15 servers), and Network-3 (300 nodes, 30 servers) under workloads of 1,250, 3,000, and 5,000 tasks across arrival profiles T1 (urgent telemetry), T2 (balanced mixed), and T3 (compute-heavy).
  2. Multi-Attribute Priority Scoring (priority.py): Computes a composite priority score Si = 0.45·Urgency + 0.35·Criticality + 0.20·ResourceIntensity for every task and classifies each into P1 (weight 1.60), P2 (1.25), P3 (1.00), or P4 (0.75), yielding an empirical P1–P4 distribution per experiment.
  3. Seven-Rule Resource Filtering (resource_filter.py): Enforces Available CPU, RAM, Storage, and Bandwidth sufficiency alongside Estimated Latency ≤ 50 ms, Projected CPU Utilization ≤ 85%, and Projected RAM Utilization ≤ 90%.
  4. Hierarchical Game Coordination (stackelberg.py, nash_mfg.py, hierarchical_game.py): Edge servers optimize Stackelberg unit prices while follower nodes compute damped fixed-point Mean-Field Game (MFG) stationary distributions and route tasks via priority-weighted congestion potentials across four policy variants: A1: MFG only, A2: Stackelberg only, A3: MFG+Stackelberg, and Proposed.
  5. Queue Execution & Independent Equilibrium Auditing (edge_node.py, metrics.py): Tasks execute against real node queue clocks (next_available_time_ms), and post-allocation perturbation verifiers independently compute the Final Nash Gap (↓) and Stackelberg Gap (↓).

7. Methodological Notes & Interpretation Cautions

  • Pooled vs. Condition-Specific Means: Overall summary tables combine three network sizes, three load levels, and three priority profiles. Condition-level tables should be interpreted alongside pooled results.
  • Matched Environmental Seeds: Within each replication, all four policy variants observe the exact same task batch and initial node capacities.
  • Utilization-Based Fairness: Jain's Fairness and Load Variance measure composite post-allocation hardware utilization (65% CPU + 35% RAM) across edge nodes.
  • Independent Equilibrium Verification: Final Nash Gap and Stackelberg Gap are evaluated by post-allocation perturbation audits, leaving inapplicable solver components as N/A.
